# Ресторан — демо-версия

Статичный сайт для показа ресторанной версии: **лаунчер** с тремя приложениями (официант, кухня, админка),
режимом «Официант + кухня» рядом, виртуальным принтером кухни, **руководством пользователя** и его **PDF-версией**.
Сервер не нужен: вместо него в браузере работает эмулятор API (`assets/demo-server.js`), данные демо-ресторана
«Навруз» хранятся в `localStorage` браузера и общие для всех вкладок — заказ официанта сразу появляется на кухне.

## Как открыть

Любой статический веб-сервер, корень — эта папка:

```bash
php -S 127.0.0.1:8080 -t demo
```

Затем откройте http://127.0.0.1:8080/. В Chrome и Edge можно открыть `index.html` и двойным щелчком;
Firefox изолирует локальные файлы друг от друга, и официант с кухней перестают видеть общие данные — используйте сервер.

## Публикация

Папка самодостаточна: её можно выложить на любой статический хостинг как есть. Для GitHub Pages в репозитории есть
workflow `.github/workflows/demo-pages.yml` (запускается вручную и только из основной ветки — после слияния):
включите **Settings → Pages → Source: GitHub Actions**, затем **Actions → «Демо ресторана на GitHub Pages» →
Run workflow**. Демо откроется по адресу `https://<владелец>.github.io/<репозиторий>/`.

## Что внутри

| Файлы | Что это | Откуда |
|---|---|---|
| `index.html`, `assets/launcher.js`, `assets/launcher.css` | лаунчер | правятся здесь |
| `assets/demo-server.js` | эмулятор API `/api/restaurant`, демо-данные, виртуальный принтер, имитация онлайн-сервера | правится здесь |
| `guide.html`, `assets/guide.css` | руководство пользователя (в лаунчере и для печати в PDF) | правятся здесь |
| `admin.html`, `waiter.html`, `kitchen.html`, `assets/{restaurant.css,common.js,admin.js,waiter.js,kitchen.js}`, `assets/icons/` | приложения — те же файлы и layout'ы, что на сервере | `php artisan restaurant:demo-site` |
| `guide/*.jpg`, `restaurant-guide.pdf` | скриншоты для руководства и PDF (A4) | `node demo/tools/build-guide.cjs` |

Сгенерированные файлы руками не правьте — они перезаписываются.

## Пересборка после изменений в приложениях

```bash
php artisan restaurant:demo-site
```

Команда копирует скрипты и стили из `public/restaurant` и рендерит страницы из `resources/views/restaurant`
с подключённым эмулятором. Тест `tests/Feature/Restaurant/DemoSiteTest.php` падает, если `demo/` отстал от приложений.

Скриншоты и PDF (нужен Playwright с Chromium: `npm i -D playwright && npx playwright install chromium`):

```bash
node demo/tools/build-guide.cjs
```

```bash
node demo/tools/build-guide.cjs --pdf-only
```

Скрипт сам поднимает веб-сервер для `demo/`, проходит сценарий на свежих демо-данных (заказ с комментарием,
дозаказ, отмена, кухня, оплата, все разделы админки) и печатает `guide.html` в PDF.

## Чем демо отличается от рабочей версии

- **Данные** — только в этом браузере; кнопка «Начать демо заново» возвращает исходное состояние. Если демо долго
  не открывали, время заказов сдвигается вперёд, чтобы таймеры и «сегодня» в отчётах оставались правдоподобными.
- **Принтер** виртуальный: чеки появляются на ленте раздела «Принтер кухни» в лаунчере. Если выключить принтер
  (там же или в «Режимах демо» на обзоре), чеки встают в очередь, а после включения печатаются по порядку.
- **Онлайн-сервер** имитируется: синхронизация проходит мгновенно, переключатель «Сбой связи с онлайн-сервером»
  показывает ошибку и пометку «есть неотправленные данные».
- **Касса и склад** открываются в отдельной демо-версии кассы: https://asadbek8364-oss.github.io/kassa-demo/
- PWA и service worker в демо отключены — установка на устройство есть только в рабочей версии.
