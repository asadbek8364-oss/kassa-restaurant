# Касса и склад

Мобильное веб-приложение для магазинов аксессуаров для телефонов: продажи, склад, приход, возвраты,
инвентаризация, отчёты, прогнозы, журнал и сотрудники. Один владелец может вести несколько магазинов.
Клиент — статические файлы в `public/kassa/`. Данные хранятся на сервере этого Laravel-приложения
(таблицы `kassa_*`, по умолчанию в одном файле SQLite), там же выполняются все расчёты и прогнозы.
Если сервер недоступен, продавец продолжает пробивать чеки — они копятся на телефоне и уходят на сервер сами.

## Развёртывание на чистом сервере (Ubuntu 24.04)

Эти шаги проверены на чистом клоне: `composer install --no-dev`, SQLite, nginx + PHP-FPM 8.3, `APP_ENV=production`.
Не проверены только получение HTTPS-сертификата (certbot) и DNS — их нужно сделать на своём домене.

```bash
# 1. Пакеты: PHP 8.3 с расширениями, nginx, git, composer
sudo apt update
sudo apt install -y nginx git unzip curl openssl \
  php8.3-fpm php8.3-cli php8.3-sqlite3 php8.3-mbstring php8.3-xml php8.3-curl \
  php8.3-zip php8.3-intl php8.3-gd php8.3-bcmath
curl -sS https://getcomposer.org/installer | php && sudo mv composer.phar /usr/local/bin/composer

# 2. Код
sudo git clone -b main \
  https://github.com/asadbek8364-oss/point-of-sales.git /var/www/kassa
sudo chown -R $USER /var/www/kassa
cd /var/www/kassa
composer install --no-dev --optimize-autoloader

# 3. Настройки: .env.example уже рассчитан на рабочий сервер (production, debug выключен, SQLite)
cp .env.example .env
php artisan key:generate --force
sed -i "s|^APP_URL=.*|APP_URL=https://kassa.example.uz|; s|^SANCTUM_STATEFUL_DOMAINS=.*|SANCTUM_STATEFUL_DOMAINS=kassa.example.uz|" .env
sed -i "s|^KASSA_SETUP_CODE=.*|KASSA_SETUP_CODE=$(openssl rand -hex 6)|" .env
grep KASSA_SETUP_CODE .env          # запишите код — он понадобится в мастере один раз

# 4. База SQLite и кэш маршрутов
touch database/database.sqlite
php artisan migrate --force
php artisan route:cache && php artisan view:cache && php artisan event:cache
sudo chown -R www-data:www-data storage bootstrap/cache database
```

`php artisan config:cache` и `php artisan optimize` не используйте: настройки документации API
основного приложения (`config/scramble.php`) не кэшируются. Деплой самого репозитория тоже их не кэширует.

5. nginx — `/etc/nginx/sites-available/kassa` (замените домен):

```nginx
server {
    listen 80;
    server_name kassa.example.uz;
    root /var/www/kassa/public;
    index index.html;
    charset utf-8;
    client_max_body_size 2m;

    add_header X-Content-Type-Options nosniff always;
    add_header Referrer-Policy same-origin always;

    # Корень сайта открывает кассу; остальная часть POS-системы на этом сервере закрыта.
    location = / { return 302 /kassa/; }
    location /kassa/ { try_files $uri $uri/ =404; }
    location = /kassa/sw.js { add_header Cache-Control "no-cache" always; try_files $uri =404; }

    # API кассы обрабатывает Laravel.
    location /api/kassa/ { try_files $uri /index.php?$query_string; }
    location = /index.php {
        internal;
        include snippets/fastcgi-php.conf;
        fastcgi_pass unix:/run/php/php8.3-fpm.sock;
    }

    location / { return 404; }
}
```

```bash
sudo ln -s /etc/nginx/sites-available/kassa /etc/nginx/sites-enabled/kassa
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl reload nginx

# 6. HTTPS (обязательно: без него не работают камера-сканер, установка на телефон и защищённые cookie)
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d kassa.example.uz
```

7. Откройте `https://kassa.example.uz` — откроется мастер первого запуска. Введите:
   - код установки из `.env`;
   - название магазина;
   - имя владельца;
   - свой PIN (4–6 цифр).

   Дальше владелец добавляет товары и продавцов, у каждого продавца свой PIN.

С таким конфигом снаружи открыты только `/kassa/` и `/api/kassa/`. Остальная POS-система (`/setup`, `/login`, `/api/v1`),
файл `.env` и файл базы снаружи недоступны.

### Обновление

Миграции переносят существующие данные без ручных шагов: всё, что было до появления нескольких магазинов,
относится к первому магазину, владельцы становятся общими для всех магазинов, продавцы остаются в нём.

```bash
cd /var/www/kassa
git pull
composer install --no-dev --optimize-autoloader
# база, storage и bootstrap/cache принадлежат www-data — artisan запускаем от его имени
sudo -u www-data php artisan migrate --force
sudo -u www-data php artisan route:cache
sudo -u www-data php artisan view:cache
sudo -u www-data php artisan event:cache
```

(`sudo apt install sqlite3`). Добавьте эту команду в `cron` раз в день и храните копии вне сервера.

## Первый запуск и безопасность

- **Демо-данных нет.** При первом открытии — мастер: код установки, название магазина, владелец и его собственный PIN.
- **Код установки** (`KASSA_SETUP_CODE`) защищает мастер: без него посторонний мог бы создать магазин раньше владельца.
  На рабочем сервере (`APP_ENV=production`) без заданного кода мастер закрыт и показывает, что нужно сделать.
  После создания магазина мастер больше не открывается.
- **PIN** — 4–6 цифр. Сервер отклоняет простые: одинаковые цифры (1111), подряд (1234, 4321), частые (2580, 1212 и т. п.).
- После 5 неверных PIN подряд вход этого сотрудника закрыт на 15 минут.
- PIN и токены входа хранятся только в виде хешей. Вход действует 30 дней с продлением при активности (`KASSA_TOKEN_TTL_DAYS`).
- Отключённый сотрудник сразу теряет доступ.
- Только владелец может: создавать магазины и переключаться между ними, смотреть сводку по всем магазинам,
  удалять товары, добавлять, изменять и отключать сотрудников, менять название и адрес магазина.
  Продавцы продают, принимают приход, оформляют возвраты и инвентаризацию, добавляют и меняют товары — только в своём магазине.
- У каждого маршрута свой лимит запросов (`kassa-public`, `kassa-setup`, `kassa-login`, `kassa-api` в `AppServiceProvider`).
  Счётчики раздельные, потому что все телефоны магазина обычно выходят в сеть с одного IP.

## База данных

По умолчанию — SQLite, файл `database/database.sqlite`. Отдельный сервер базы не нужен.
Для одновременной работы нескольких касс в `config/database.php` включены:

| Настройка | Значение | Зачем |
|-----------|----------|-------|
| `DB_JOURNAL_MODE` | `wal` | Чтение не ждёт записи |
| `DB_BUSY_TIMEOUT` | `10000` | Касса ждёт до 10 с, пока другая запишет, вместо ошибки «database is locked» |
| `DB_TRANSACTION_MODE` | `IMMEDIATE` | Транзакция сразу занимает запись (PHP 8.4+) |
| `DB_SYNCHRONOUS` | `normal` | Рекомендуемый режим для WAL |

На PHP 8.3 тот же порядок гарантирует сама касса: первая команда каждой операции — запись в строку магазина.
Проверено: 10 параллельных процессов продают товар с остатком 3 — 3 продажи, 7 отказов «недостаточно на складе»,
номера чеков подряд, без ошибок блокировки. Все миграции проекта проходят на чистом SQLite.

Папка `database/` должна быть доступна PHP на запись: рядом с базой создаются файлы `-wal` и `-shm`.
Для MySQL укажите `DB_CONNECTION=mysql` и параметры подключения в `.env`.

## Несколько магазинов

- **Магазин** (`kassa_stores`) — название, адрес и своя нумерация документов (чеки с 1001, приходы, возвраты и
  инвентаризации с 1). Первый магазин создаёт мастер первого запуска, следующие — владелец:
  «Ещё → Магазины → Добавить» или название магазина в шапке → «Новый магазин».
- **Изоляция.** Товары, чеки, возвраты, приходы, инвентаризации и их позиции хранят `store_id`. Глобальный scope
  `StoreScope` (трейт `BelongsToStore`) добавляет `store_id = <текущий магазин>` к каждому запросу этих моделей,
  в том числе к подстановке моделей из маршрута (`/products/{id}` чужого магазина → 404) и к запросам отчётов с `join`.
  Штрих-код уникален в пределах магазина: один и тот же товар может быть в двух магазинах.
- **Сотрудники.** Продавец работает в одном магазине (`store_id`), владелец — во всех (`store_id = NULL`).
  В магазине видны его продавцы и владельцы; продавца добавляют, находясь в нужном магазине.
- **Текущий магазин** хранится в токене входа (`kassa_tokens.store_id`). Продавец всегда попадает в свой магазин;
  владелец входит в магазин телефона и переключается (`POST /stores/{id}/switch`) — это меняет магазин только
  для его входа на этом устройстве. Телефон помнит свой магазин, экран входа показывает его сотрудников и
  позволяет выбрать другой магазин. Корзина, приход и пересчёт хранятся на телефоне отдельно для каждого магазина.
- **Сводка владельца** (`GET /stores?period=today|week|month`): по каждому магазину выручка, чеки, средний чек,
  валовая прибыль, стоимость склада, «мало на складе», «скоро закончатся» и деньги в товарах без продаж — и итог
  по всем магазинам. Каждый магазин считается теми же отчётами, что и сам магазин (`StoreContext::run`).

## Прогнозы

Обычная статистика на сервере (`app/Services/Kassa/KassaForecastService.php`), без внешних сервисов.

1. **История.** Для каждого товара — ряд «продано штук за день» за последние **28 полных дней** в часовом поясе
   магазина. Сегодняшний неполный день не учитывается; у нового товара ряд начинается со дня его создания.
2. **Скользящее среднее.** `avg` — среднее ряда (окно 28 дней сдвигается каждый день); для справки — `avg_7` за 7 дней.
3. **Тренд.** Наклон прямой по методу наименьших квадратов, шт/день за день (`trend_pct` — то же в % от среднего за неделю).
   Учитывается, если в ряду не меньше 14 дней.
4. **Спрос в день** = `avg + наклон × (n + 14) / 2` — значение линии тренда в середине горизонта прогноза
   (14 дней). Поправка на тренд ограничена ±50 % от среднего, спрос не меньше нуля.
5. **Остатка хватит на N дней** = остаток / спрос в день (вниз до целого); нет спроса — срок не считается.
6. **К заказу** = спрос × 14 + минимальный остаток − остаток (вверх до целого): запас на две недели плюс страховой минимум из карточки.
7. **«Мёртвый» товар** — есть на складе и не продавался 30+ дней (или ни разу с момента создания);
   заморожено = остаток × закупочная цена. Срок можно выбрать: 30, 60 или 90 дней.

Раздел «Прогнозы» (`GET /forecasts?threshold=3|7|14&dead_days=30|60|90`): товары, которые закончатся раньше порога
(по умолчанию 7 дней), с количеством и суммой к заказу и кнопкой «В приход»; товары без продаж с замороженной суммой.
На главном экране — короткий виджет (`forecast` в `GET /dashboard`), в карточке товара — его прогноз (`forecast` в `GET /products/{id}`).
Ограничение: дни, когда товара не было на складе, считаются днями без продаж и занижают спрос.

## Работа без связи

- Приложение (оболочка) открывается без сети благодаря `sw.js`. После каждого входа телефон хранит копию входа,
  магазина и каталога (`kassa-sklad:snapshot:v1`), поэтому без связи можно открыть кассу и продавать.
- Если сервер не ответил на чек (нет сети, таймаут 12 с, ответ 502/503/504), чек сохраняется в очередь на устройстве
  (`kassa-sklad:queue:v1`) с тем же `client_uuid`, временем продажи по часам телефона, ценами из каталога телефона и
  суммой `client_total`. Остатки на телефоне сразу уменьшаются на чеки из очереди. Пока связи нет, следующие чеки
  сразу идут в очередь; вверху экрана видно, сколько чеков ждёт отправки.
- Очередь уходит сама: при появлении сети, при возвращении в приложение и каждые 15 секунд — `POST /api/kassa/sales/sync`
  (до 20 чеков за запрос, сервер принимает до 50). Каждый чек обрабатывается отдельно и в своём магазине; результат —
  `created`, `replay` (уже был) или `rejected` (с причиной, чек остаётся на телефоне с пометкой).
- **Без дублей.** `client_uuid` уникален в базе: повторная отправка (ответ потерялся, две вкладки, чек, который на самом
  деле дошёл онлайн) возвращает уже сохранённый чек, остатки второй раз не списываются.
- Чек уходит под тем сотрудником, который его пробил: если на телефоне вошёл другой сотрудник, чеки ждут входа автора
  (при выходе приложение об этом предупреждает). Продавец может отправить чеки только своего магазина, владелец — любого.

### Правило разрешения конфликтов по остаткам

Офлайн-чек — свершившийся факт: товар уже у покупателя, деньги в кассе. Поэтому сервер **никогда не отклоняет его из-за
остатков** (в отличие от онлайн-продажи, где «недостаточно на складе» — ошибка):

1. Товар списывается, сколько есть, **остаток не уходит ниже нуля**. Если пока чек ждал отправки, товар продали
   с другого телефона, недостающее количество записывается в позицию чека (`kassa_sale_items.shortage`).
   Чек и позиция помечаются как расхождение: в журнале и в чеке — «расхождение», «не было на складе при отправке: N шт».
2. Продажа учитывается полностью: выручка, проданные штуки, себестоимость и прогнозы считают всё количество чека.
3. **Цены — серверные**, как у обычного чека; сумма с телефона сохраняется в `client_total`. Если цену изменили, пока
   чек ждал отправки, чек тоже помечается расхождением и в нём видны обе суммы.
4. Товар, удалённый из каталога, пока чек ждал отправки, записывается по названию и цене с телефона, без списания
   (вся строка — расхождение).
5. Время продажи — по часам телефона, если оно не в будущем и не старше 30 дней; иначе — время сервера.
   Номер чека выдаётся при отправке, поэтому офлайн-чек может получить номер больше, чем чеки, пробитые после него.
6. Расхождения закрывает человек: инвентаризация выставляет фактический остаток, приход добавляет неоприходованный товар.
   Автоматически сервер остатки «в минус» не переносит.

Пример: последний чехол (остаток 1) продали без связи на двух телефонах. Первый пришедший чек списывает его (остаток 0),
второй сохраняется с расхождением 1 шт; оба чека — в выручке, остаток 0, владелец видит расхождение в журнале.

## Что считает сервер

| Операция | Что делает сервер |
|----------|-------------------|
| Продажа `POST /api/kassa/sales` | Берёт розничные цены из базы (цены от клиента игнорируются), проверяет остатки, считает итог, себестоимость и сдачу, списывает товар, присваивает номер чека, записывает продавца по токену. Повтор с тем же `client_uuid` не создаёт второй чек |
| Возврат `POST /api/kassa/returns` | Не даёт вернуть больше купленного минус уже возвращённое, считает сумму по цене из чека, возвращает товар на склад |
| Приход `POST /api/kassa/incomes` | Увеличивает остатки, обновляет закупочную цену, считает сумму документа |
| Инвентаризация `POST /api/kassa/audits` | Фиксирует учётный остаток на момент проведения и выставляет остаток по факту; считает недостачу и излишек |
| Офлайн-чеки `POST /api/kassa/sales/sync` | Принимает очередь чеков с телефона по правилу конфликтов выше; повтор `client_uuid` не создаёт второй чек |
| Отчёты `GET /api/kassa/reports?period=today\|week\|month\|all` | Выручка, чеки, проданные единицы, средний чек, валовая прибыль и маржа; график по часам, дням или месяцам; оплаты, продавцы, топ товаров, низкие остатки, стоимость склада |
| Главная `GET /api/kassa/dashboard` | Итоги дня, товары с низким остатком, последние продажи, короткий прогноз |
| Прогнозы `GET /api/kassa/forecasts` | Что закончится раньше порога и сколько заказать, товары без продаж и замороженная сумма |
| Сводка `GET /api/kassa/stores` | Показатели каждого магазина и итог по всем (владелец) |
| Журнал `GET /api/kassa/journal` | Все операции по убыванию времени, фильтр по типу, поиск, итог выручки за каждый день |

Все отчёты, журнал и прогнозы считаются по текущему магазину.
Формулы: выручка = продажи − возвраты (возврат учитывается в день возврата); средний чек = продажи / число чеков;
валовая прибыль = выручка − себестоимость (закупочная цена на момент продажи).
«Сегодня», неделя и месяц считаются в часовом поясе магазина `KASSA_TIMEZONE` (по умолчанию `Asia/Tashkent`).

## Что хранится на телефоне

- Черновики по каждому магазину: корзина, незаконченный приход и пересчёт инвентаризации.
- Токен входа и магазин этого телефона.
- Копия каталога и входа для работы без связи и очередь неотправленных чеков (см. «Работа без связи»).

Всё остальное приходит с сервера. При возвращении в приложение данные обновляются, так что продажи с других
телефонов сразу видны.

## API

Все запросы — JSON. Всем, кроме `options`, `setup` и `login`, нужен заголовок `Authorization: Bearer <token>`.

| Метод и путь | Назначение |
|--------------|------------|
| `GET /api/kassa/options?store_id=` | Магазины, выбранный магазин и его сотрудники для экрана входа, нужна ли первая настройка, нужен ли код установки |
| `POST /api/kassa/setup` | Первая настройка (только пока нет сотрудников): `setup_code`, `store_name`, `owner_name`, `pin` |
| `POST /api/kassa/login`, `POST /api/kassa/logout` | Вход по `employee_id` + `pin` (+ `store_id` телефона для владельца), выход |
| `GET /api/kassa/ping` | Проверка связи для офлайн-очереди |
| `GET /api/kassa/bootstrap` | Кто вошёл, магазин, список магазинов (владельцу), сотрудники, каталог, популярные товары, поставщики |
| `GET/POST /api/kassa/products`, `GET/PUT/DELETE /api/kassa/products/{id}`, `GET /api/kassa/products/barcode` | Каталог, карточка с движением товара, новый внутренний EAN-13 |
| `GET/POST /api/kassa/sales`, `GET /api/kassa/sales/{id}` | Чеки (`?number=` — поиск по номеру) |
| `POST /api/kassa/sales/sync` | Очередь чеков, пробитых без связи: `sales[]` с `client_uuid`, `store_id`, `sold_at`, `payment`, `items[]` (`product_id`, `qty`, `name`, `price`), `client_total` |
| `GET /api/kassa/forecasts?threshold=&dead_days=` | Прогнозы |
| `GET/POST /api/kassa/returns`, `GET /api/kassa/returns/{id}` | Возвраты |
| `GET/POST /api/kassa/incomes`, `GET /api/kassa/incomes/{id}` | Приходы |
| `GET/POST /api/kassa/audits`, `GET /api/kassa/audits/{id}` | Инвентаризации |
| `GET /api/kassa/dashboard`, `/reports`, `/journal` | Сводки и отчёты текущего магазина |
| `GET /api/kassa/employees`, `/employees/{id}` | Сотрудники со статистикой |
| `POST /api/kassa/employees`, `PUT /employees/{id}`, `POST /employees/{id}/toggle` | Управление сотрудниками (владелец) |
| `PUT /api/kassa/store` | Название и адрес текущего магазина (владелец) |
| `GET /api/kassa/stores?period=`, `POST /api/kassa/stores` | Сводка по всем магазинам, новый магазин (владелец) |
| `POST /api/kassa/stores/{id}/switch` | Переключить вход владельца на другой магазин |

## Разработка на своём компьютере

```bash
cp .env.example .env
# APP_ENV=local, APP_DEBUG=true, APP_URL=http://localhost:8000, SESSION_SECURE_COOKIE=false
# по желанию KASSA_DEMO_ENABLED=true для демо-магазинов
php artisan key:generate
touch database/database.sqlite && php artisan migrate
php artisan serve        # http://localhost:8000/kassa/index.html
php artisan test --filter=Kassa
```
