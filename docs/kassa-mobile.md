# Касса и склад на планшете и телефонах

Касса — веб-приложение на сервере (`public/kassa/`). Его можно открыть тремя способами:

| Способ | Что нужно | Когда подходит |
|--------|-----------|----------------|
| Браузер или установка на главный экран (PWA) | Ничего, кроме HTTPS на сервере | Сразу, на любом телефоне и планшете |
| Приложение для Android (`mobile/android`) | Android Studio, для Google Play — аккаунт разработчика | Нужна иконка из APK, Google Play или установка APK на кассы магазина |
| Приложение для iPhone и iPad (`mobile/ios`) | Mac с Xcode и аккаунт Apple Developer | Нужна установка через App Store, TestFlight или Ad Hoc |

Обе обёртки открывают `https://ablazov.duckdns.org/kassa/` на весь экран, без панелей браузера, с иконкой и названием
«Касса и склад». Вся логика, данные и расчёты — на сервере, как и в браузере; обновлять приложения при изменениях
кассы не нужно.

## Планшет

С ширины экрана 768 px (планшет, телефон в альбомной ориентации) включается планшетная вёрстка:

- **Продажа** — две колонки: слева весь каталог плитками с поиском и категориями (без поиска сначала популярные),
  справа корзина, оплата и кнопка «Пробить чек»; правая колонка остаётся на месте при прокрутке каталога.
- **Отчёты, журнал, товары, прогнозы, сводка по магазинам** — на всю ширину (до 1200 px), показатели отчётов — в ряд.
- Листы (чек, карточка товара) и диалоги остаются шириной с телефон по центру экрана.

Ниже 768 px вёрстка телефонная, как раньше. При повороте планшета экран перестраивается сам.

## Установка веб-версии на главный экран (PWA)

Проверено в Chromium (`Page.getInstallabilityErrors` — ошибок нет): манифест `public/kassa/manifest.webmanifest`
(`display: standalone`, `id`, иконки 192/512, отдельная маскируемая 512, ориентация любая, ярлыки «Продажа», «Приход»,
«Прогнозы»), Service Worker `public/kassa/sw.js`, значок `apple-touch-icon.png` 180×180 для iPhone.

- **Android (Chrome):** откройте `https://<домен>/kassa/` → меню ⋮ → «Установить приложение» (или «Добавить на главный экран»).
- **iPhone/iPad (Safari):** кнопка «Поделиться» → «На экран „Домой“».

Установленная касса открывается без адресной строки. Оболочка кэшируется Service Worker'ом, поэтому касса запускается
и без связи (по сохранённой копии каталога), а если сервер за nginx отвечает 502/503/504 — тоже открывается сохранённая
оболочка. Без HTTPS установка и камера не работают.

## Что делают приложения-обёртки

| | Android (`MainActivity.kt`) | iOS (`WebViewController.swift`) |
|---|---|---|
| Экран | WebView на весь экран, отступы под системные панели и клавиатуру | WKWebView на весь экран, отступы «чёлки» и полосы «Домой» — через CSS `env(safe-area-inset-*)` |
| Камера-сканер | Разрешение `CAMERA` запрашивается при первом сканировании, затем выдаётся странице (`getUserMedia`) только для домена кассы | `NSCameraUsageDescription`; странице кассы камера выдаётся без лишнего вопроса браузера |
| Штрих-код по фото | `<input capture>` открывает камеру телефона (снимок через `FileProvider`) | WKWebView открывает камеру сам |
| Камера запрещена | В сканере кнопка «Открыть настройки» → настройки приложения | То же → настройки приложения |
| Офлайн-оболочка | Service Worker страницы (включён в WebView) | Service Worker включается только для App-Bound Domains — домен кассы указан в `WKAppBoundDomains` |
| Очередь офлайн-чеков | `localStorage` + копия в `SharedPreferences` (синхронная запись) | `localStorage` + копия в файле приложения |
| Нет сети при первом запуске | Экран «Нет связи с сервером», касса открывается сама, когда сеть появилась | То же (`NWPathMonitor`) |
| Кнопка «Назад» | Закрывает диалог, сканер, лист, затем ведёт на главную, затем сворачивает приложение | Жест «назад» листает историю страницы |
| Чужие ссылки | Открываются в браузере или другом приложении | То же |

**Зачем копия очереди.** WebView записывает `localStorage` на диск с задержкой. Если закрыть приложение сразу после
чека без связи, запись могла не успеть. Поэтому страница после каждого изменения очереди отдаёт её копию обёртке
(`KassaAndroid.saveQueue` / `webkit.messageHandlers.kassa`), а при запуске добавляет из копии чеки, которых нет в
`localStorage`. Лишний (уже отправленный) чек из устаревшей копии безопасен: сервер узнает его по `client_uuid` и не
создаст дубль. Правило конфликтов по остаткам — в `docs/kassa-sklad.md`.

**Мост для страницы** (в `public/kassa/app.js` — объект `NATIVE`): `openSettings()`, `saveQueue(json)`, `loadQueue()`.
Обёртки добавляют к User-Agent `KassaSklad-Android/1.0` или `KassaSklad-iOS/1.0`. В обычном браузере моста нет,
касса работает как раньше.

**Адрес сервера** зашит в двух местах:

- Android — `mobile/android/app/build.gradle.kts`, `KASSA_URL`;
- iOS — `mobile/ios/KassaSklad/Info.plist`: ключ `KassaURL` и домен в `WKAppBoundDomains` (они должны совпадать,
  иначе WKWebView не откроет страницу).

Идентификатор приложения в обоих проектах — `org.duckdns.ablazov.kassa`. Его можно сменить (Android — `applicationId`,
iOS — `PRODUCT_BUNDLE_IDENTIFIER`) до первой публикации; после публикации в магазине он не меняется.

## Сборка APK для Android

Нужно: Android Studio (любая версия 2025 года и новее), из неё же — Android SDK 36. Проект: Android Gradle Plugin 8.13,
Kotlin 2.2, Gradle 8.14 (скачивается сам через `gradlew`), minSdk 26 (Android 8.0), targetSdk 36.

1. Android Studio → **Open** → папка `mobile/android`. Дождитесь синхронизации Gradle. Если студия предложит обновить
   Android Gradle Plugin — можно согласиться.
2. **Проверка на телефоне:** включите на телефоне «Для разработчиков → Отладка по USB», подключите кабелем, нажмите ▶ Run.
3. **APK для установки на кассы магазина:** Build → **Generate Signed App Bundle or APK** → **APK** → создайте ключ
   (**Create new…**, файл `.jks`) → вариант **release**. Готовый файл: `mobile/android/app/release/app-release.apk`.
   Его можно скопировать на телефон и установить (Android попросит разрешить установку из этого источника).
4. **Для Google Play** в том же мастере выберите **Android App Bundle** — получится `app-release.aab`.

Ключ подписи (`.jks`) и пароли храните отдельно и не теряйте: обновления подписываются тем же ключом
(в Google Play при включённой подписи Google теряется только ключ загрузки, его можно восстановить через поддержку).
В репозиторий ключ не добавляйте (`*.jks` в `.gitignore`).

Из командной строки (на сервере сборки): `cd mobile/android && ./gradlew assembleDebug` — отладочный APK в
`app/build/outputs/apk/debug/`; `./gradlew bundleRelease` / `assembleRelease` — после настройки подписи
(`signingConfigs` в `app/build.gradle.kts` или подпись в Android Studio).

## Сборка IPA для iPhone и iPad

Нужно: **Mac** с Xcode 16 или новее. Собрать приложение для iOS на Windows или Linux нельзя. Проект: iOS 15+, iPhone и iPad,
Swift, без сторонних зависимостей.

1. Откройте `mobile/ios/KassaSklad.xcodeproj` в Xcode.
2. Цель **KassaSklad** → **Signing & Capabilities** → **Team**: выберите свою команду (Apple ID добавляется в
   Xcode → Settings → Accounts). При необходимости поменяйте **Bundle Identifier**.
3. **Проверка на своём iPhone:** подключите телефон, выберите его вверху и нажмите ▶ Run. С бесплатным Apple ID
   приложение работает 7 дней, затем его нужно установить заново.
4. **IPA:** выберите устройство «Any iOS Device (arm64)» → Product → **Archive** → в окне Organizer → **Distribute App**:
   - **App Store Connect** — для TestFlight и App Store;
   - **Ad Hoc** — IPA для зарегистрированных устройств (до 100 iPhone и 100 iPad в год, их UDID добавляются в аккаунте разработчика);
   - **Custom App / Enterprise** — для организаций с Apple Business Manager или Enterprise-аккаунтом.

Из командной строки на Mac: `xcodebuild -project mobile/ios/KassaSklad.xcodeproj -scheme KassaSklad -configuration Release -archivePath build/KassaSklad.xcarchive archive`, затем `xcodebuild -exportArchive` с файлом `ExportOptions.plist`.

## Аккаунты разработчика и магазины приложений

- **Google Play:** аккаунт Google Play Console (разовый взнос 25 $). Для нового личного аккаунта Google требует закрытое
  тестирование до выхода в продакшн. Понадобятся иконка 512×512 (`public/kassa/icon-512.png`), скриншоты, политика
  конфиденциальности (приложение использует камеру), анкета о содержании. APK можно раздавать и без Google Play —
  напрямую на телефоны магазина.
- **App Store / TestFlight:** участие в Apple Developer Program (99 $ в год), приложение создаётся в App Store Connect.
  TestFlight позволяет раздать сборку до 10 000 тестировщиков (сборка действует 90 дней).
- **Важно про модерацию.** Обе площадки внимательно смотрят на приложения, которые только показывают сайт
  (App Store — правило 4.2 «Minimum Functionality», Google Play — политика о минимальной функциональности).
  Для своего магазина надёжнее раздавать Android-приложение как APK, а iPhone — через TestFlight, Ad Hoc
  или Custom App (Apple Business Manager), либо ставить веб-версию на главный экран (PWA) — она умеет то же самое.

## Что проверено

- Планшетная вёрстка — Playwright: 390, 768 и 1180 px, без горизонтальной прокрутки, телефонная вёрстка не изменилась.
- PWA — Chromium: установка без ошибок, Service Worker управляет страницей, запуск без сети и при ответе сервера 503
  открывает сохранённую кассу.
- Мост — Playwright с имитацией `window.KassaAndroid`: чек из копии обёртки восстановлен и отправлен без дублей,
  копия очищена после отправки; «Открыть настройки» при запрете камеры; «Назад» закрывает сканер и ведёт на главную.
- Android — проект собран в Linux-контейнере: `assembleDebug` (APK 2,6 МБ), `assembleRelease` с R8 (168 КБ, без подписи), `lintDebug` — 0 ошибок. На реальном телефоне не запускался.
- iOS — собрать без Mac нельзя: проверены структура проекта Xcode (парсер `pbxproj`), `Info.plist`, каталог ресурсов,
  иконка 1024×1024 без прозрачности и синтаксис Swift (`swiftc -parse`). Первую сборку нужно сделать в Xcode на Mac.
